## 1. Project Overview

EMP 0.2 is an Examination Management Portal engineered specifically for academic evaluation, oral vivas, practical labs, and presentation scheduling. Designed with clean App–Model–View (AMV) architecture, the portal streamlines examination lifecycles across three distinct roles:

1. **Administrator**: Oversees academic courses, examination definitions, timeline windows, evaluation rubrics, examiner approvals, slot allocations, and student bookings with rescheduling and audit logging.
2. **Examiner**: Schedules examination time slots within configured windows, manages student bookings, evaluates student performance against structured rubrics, awards marks, and controls result publication.
3. **Student**: Discovers published examinations, books available slots with assigned examiners, manages active bookings, cancels prior to deadlines, and inspects published results with rubric feedback.

## 5. Local Setup & Running Instructions

### Prerequisites
- Python 3.10+ (Recommended Python 3.12)
- Windows PowerShell or Command Prompt

### Step 1: Create and Activate Virtual Environment
Open PowerShell in the project directory:
```powershell
python -m venv venv
venv\Scripts\activate
```

### Step 2: Install Minimal Dependencies
```powershell
pip install -r requirements.txt
```

### Step 3: Initialize Database and Default Admin
Run the initialization script. This creates `instance/emp.db`, sets up all relational tables, and provisions the default administrator account:
```powershell
python init_db.py
```

*Output:*
```text
-> Database schema verified / created successfully.
-> Default Admin created: admin@emp.gov / admin123
-> Sample Course 'MAD101' created.
-> Database initialization complete!
```

### Step 4: Run the Flask Application
```powershell
python app.py
```

### Step 5: Access the Portal
Open your web browser and navigate to:
```text
http://127.0.0.1:5000
```

## 6. Default Credentials & Role Testing Guide

| Role | Email | Password | Access Status |
|:---|:---|:---|:---|
| **Administrator** | `admin@emp.gov` | `admin123` | Active (Pre-created by `init_db.py`) |
| **Examiner** | Register via `/register/examiner` | *user defined* | Requires Admin Approval in Admin > Examiners |
| **Student** | Register via `/register/student` | *user defined* | Active immediately |

### Recommended Demonstration Workflow for Viva:
1. **Login as Admin** (`admin@emp.gov` / `admin123`).
2. **Review Courses**: A sample course `MAD101` is pre-created; you can add additional courses.
3. **Register Examiner**: In an Incognito window or after logging out, submit an Examiner application.
4. **Approve Examiner**: Back in Admin, go to **Examiners** and click **Approve**.
5. **Create Examination**: Go to **Examinations**, create an exam (e.g., "End-Term Viva Voce"), configure timelines, and assign the approved examiner.
6. **Configure Rubrics**: Click **Rubrics** for the examination and add scoring criteria (e.g., "Code Quality" - 30 marks, "Viva Explanation" - 70 marks). Toggle exam to **Published**.
7. **Examiner Schedules Slots**: Log in as Examiner, navigate to **My Slots**, and create time slots during the open slot creation window.
8. **Student Books Slot**: Register a student, browse available examinations under **Examinations**, select a slot, and click **Book Slot**.
9. **Examiner Evaluates**: Log back in as Examiner, open **My Students**, click **Evaluate**, input rubric marks and remarks, check **Publish Results**, and submit.
10. **Student Views Result**: Log in as Student and check **Results** to view the breakdown and examiner feedback.

## 7. Strict Business Rules Enforced

1. **No Public Admin Registration**: The Administrator is seeded exclusively through `init_db.py`.
2. **Examiner Approval Gate**: Registered examiners cannot schedule slots or evaluate until approved by the Administrator.
3. **Timeline Guards**:
   - Examiners can only create slots while `slot_creation_start <= current_time <= slot_creation_end`.
   - Students can only book slots while `booking_start <= current_time <= booking_end`.
4. **Anti-Duplicate Booking**: A student can only have one confirmed slot per examination.
5. **Capacity Protection**: Slots cannot be overbooked. Once capacity reaches zero, the slot becomes `Full`.
6. **Cancellation Deadlines**: Students can cancel bookings only prior to the examination booking deadline; cancelled seats are immediately restored.
7. **Examiner Isolation**: Examiners can evaluate only students booked into their own slots.
8. **Rubric Bounds**: Evaluation scores are validated on the backend to never exceed rubric criterion maxima or examination total marks.
9. **Result Privacy**: Results remain invisible to students until explicitly marked published.
10. **Audit Preservation**: All cancellations, reschedules, and reassignments are recorded in `BookingHistory`.
